# Протокол памяти проекта

Память живёт в memory/. Код — источник истины, память — вторична.

### Чтение (обязательно)
1. В начале каждой сессии прочитай ТОЛЬКО memory/index.md и state.md.
2. Перед выполнением задачи определи по index.md релевантные файлы памяти и прочитай только их (включая нужные ADR из decisions/).
3. НИКОГДА не читай journal/ и все decisions/ целиком.
4. Записи со статусом disputed и expired — игнорируй при работе, они недостоверны.
5. Если в journal/ есть файлы без пометки `processed: true` в первой строке — до начала работы АВТОМАТИЧЕСКИ выполни компакцию (команда /memory-compact), не спрашивая разрешения, и отчитайся строкой 💾. Это фоновый шаг: журнал во время сессии копит записи, а следующий старт сворачивает их в постоянную память.
6. Приступая к ЛЮБОЙ содержательной задаче (код, план, разбор), ПЕРВОЙ строкой ответа ВСЕГДА выдавай:
   🧠 Из памяти: <очень коротко, простым нетехническим языком — что учёл и какой контекст>.
   Это обязательно ДАЖЕ если релевантного мало — тогда напиши прямо: «🧠 Из памяти: проверил, по этой задаче ничего критичного». Пользователь должен на каждой задаче видеть, что память учтена — молчать нельзя.
   Пример: «🧠 Из памяти: форма заказа сейчас только показывает „спасибо“ и никуда не отправляет — учту, что кнопку надо связать с оплатой».

### Запись (обязательно)
1. Все записи в течение сессии делай ТОЛЬКО в свой журнал: memory/journal/<YYYY-MM-DD>-<случайный 4-символьный id сессии>.md. Один файл на сессию, только append. Канонические файлы памяти в течение рабочей сессии не редактируй — их меняет только компакция.
2. Триггеры записи в журнал: (а) завершена задача или её крупный этап; (б) принято или отменено техническое/продуктовое решение; (в) выявлен риск, ошибка, ограничение; (г) создан или изменён план.
3. Формат записи в журнале:
   [HH:MM] type: task-done | decision | risk | plan | note
   text: <1-3 строки телеграфом>
   evidence: <файлы/коммиты> (для decision и task-done — обязательно; запись без evidence получает пометку unverified)
4. ЗАПРЕЩЕНО записывать секреты: токены, ключи Stripe, пароли, connection strings, private keys. В проекте есть .figma-token и .godaddy-token — их содержимое в память не попадает никогда.
5. После каждой записи в журнал добавь в свой ответ пользователю строку:
   💾 Память: <тип записи> — <суть в 5-8 словах>
6. Записывай в память АВТОНОМНО, не спрашивая у пользователя разрешения на запись/сохранение. Пользователю только сообщай постфактум строкой 💾. Память лежит в папке memory/ (ВНЕ .claude/) — записи в неё идут без запроса, как обычные файлы проекта.

### Лимиты
index.md ≤ 60 строк, state.md ≤ 100, project.md ≤ 80, architecture.md ≤ 120, risks.md ≤ 60, каждый ADR ≤ 30. Телеграфный стиль. При превышении — сжимай, а не игнорируй лимит.

### Аудит
При компакции инкрементируй audit-counter в index.md. Если audit-counter ≥ 5 — сообщи пользователю: «🔍 Рекомендован аудит памяти: /memory-audit» и предложи запустить его.

---
description: Компакция памяти проекта — перенос записей из journal/ в канонические файлы памяти
---

Ты выполняешь компакцию памяти проекта. Строго по шагам:

1. Найди в memory/journal/ все файлы БЕЗ пометки `processed: true` в первой строке. Если таких нет — сообщи «Журналы пусты, компакция не требуется» и остановись.

2. Прочитай их все. Для каждой записи проверь evidence: файл существует / коммит есть в git. Запись без валидного evidence типа decision или task-done — НЕ переноси в канонические файлы, оставь в журнале с пометкой unverified.

3. Детекция конфликтов: если записи из разных журналов противоречат друг другу или действующему ADR (например, два разных решения по одному вопросу) — НЕ выбирай сам. Выведи конфликт пользователю в формате: «⚠ Конфликт: <суть>, вариант А (сессия X) vs вариант Б (сессия Y). Какой фиксируем?» и не переноси обе записи до ответа.

4. Перенос верифицированных записей:
   - task-done → state.md: перемести пункт из «В работе» в «Сделано», обнови «Дальше»;
   - decision → создай новый ADR в decisions/ по _template.md со следующим номером. Если решение отменяет существующий ADR — новому статус accepted, старому смени status на superseded-by-<новый id>. Сами старые ADR не редактируй кроме поля status;
   - risk → risks.md (добавь или обнови существующий);
   - plan → plans/ (создай/обнови файл плана);
   - note с архитектурным содержанием → architecture.md (перепиши затронутый блок целиком, снимок должен отражать текущее состояние);
   - изменения целей/скоупа → project.md.

5. Перезапись, а не накопление: state.md, architecture.md, project.md, risks.md — это снимки. Устаревшие строки удаляй, актуальные переписывай. Историю хранят только decisions/ и git.

6. Обнови index.md: даты updated, при необходимости описания. Обнови поле updated в изменённых файлах. Инкрементируй audit-counter в index.md на 1. Если после инкремента audit-counter ≥ 5 — добавь в итог рекомендацию «🔍 Рекомендован аудит памяти: /memory-audit». Соблюдай лимиты строк — при превышении сжимай формулировки.

7. В обработанные журналы допиши первой строкой `processed: true`.

8. Запусти node .claude/scripts/validate-memory.js. Если ошибки — исправь и запусти снова, до «OK».

9. Итог пользователю: 💾 Компакция: N записей → перечисли изменённые файлы; конфликты, ждущие решения (если есть); вывод валидатора.

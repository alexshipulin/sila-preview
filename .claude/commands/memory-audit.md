---

Ты — аудитор памяти проекта. У тебя чистый контекст: не доверяй памяти, доверяй только коду и git-истории. Строго по шагам:

1. Прочитай все файлы memory/ кроме journal/: index.md, project.md, architecture.md, state.md, risks.md, все decisions/, все plans/.

2. Для КАЖДОГО утверждения (факт в снимках, каждый ADR со статусом accepted, каждый риск) выполни проверку против источников истины:
   - открой файлы из evidence, проверь, что код подтверждает утверждение;
   - при необходимости используй git log / git show для проверки коммитов;
   - для утверждений без evidence попытайся найти подтверждение в коде самостоятельно.

3. Вердикт каждому утверждению:
   - CONFIRMED — код подтверждает. Действие: ничего.
   - OUTDATED — код изменился, утверждение устарело. Действие: перепиши утверждение по текущему коду, обнови evidence. Код — источник истины, спрашивать никого не нужно.
   - CONTRADICTED — код прямо противоречит. Действие: для ADR смени status на disputed; для строки в снимке — удали её и добавь корректную с evidence.
   - UNVERIFIABLE — проверить по коду невозможно (продуктовое намерение, внешняя договорённость). Действие: если это ADR type: product с истёкшим ttl — смени status на expired; если UNVERIFIABLE фиксируется второй аудит подряд (см. audit-log.md) — статус expired.

4. Обнови audit-log.md: добавь секцию с датой, таблица: утверждение (кратко) | вердикт | действие. Предыдущие секции не удаляй.

5. Для всех записей, ставших expired и требующих подтверждения человеком, сформируй в конце ответа блок:
   «❓ Требуют подтверждения (ответь да/нет по каждому):» — список в 1 строку на пункт.

6. Обнови updated и index.md (включая сброс audit-counter в 0). Соблюдай лимиты строк.

7. Запусти node .claude/scripts/validate-memory.js, добейся «OK».

8. Итог: 💾 Аудит: X CONFIRMED, Y OUTDATED (исправлено), Z CONTRADICTED (disputed), W expired. Изменённые файлы: <список>.
